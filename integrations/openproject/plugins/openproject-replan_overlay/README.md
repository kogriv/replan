# OpenProject RePlan overlay

This is the first RePlan OpenProject plugin project view.

It is intentionally read-only. The plugin renders a configured
`openproject_overlay.json` artifact generated by RePlan:

```text
reports/latest/raw/openproject_overlay.json
```

It does not calculate RePlan data, write OpenProject work packages, write
RePlan files, accept actuals, create proposals or run synchronization jobs.

## Development status

Status: first read-only project view.

The plugin has been tested in a disposable OpenProject runtime and installed in
the private RePlan self-dogfood OpenProject instance. The project page opens
with five counters that answer questions (waiting on a person, overloaded
weeks ahead, open tasks, warnings, open proposals), then the open tasks that
need attention with names, windows, resources and signals in words, and a
pointer to the Gantt page. The Gantt
page draws the plan on a date axis with resource lanes, pinned dates and task
column, closed tasks under "Done", and a weekly load profile per resource
with a 100% waterline and overload drawn as a hump above it, with range presets, from and to dates,
a days, weeks or months scale, jumps, a time slider, foldable controls, full
screen, and up to five task pages kept open as tabs. A task's page shows
the task with its resource lanes on a Gantt axis of its own, warnings and
proposals in words, what was done, planned, booked and remaining amounts,
time booked by date, and what it depends on and what waits on it, each a link
to its own page. All colours come from OpenProject's
Primer variables. The design is in
`docs/dev/openproject-plugin-redesign-design.md`.

Tests: `ruby -Ilib test/overlay_presenter_test.rb` and
`ruby -Ilib test/gantt_presenter_test.rb`,
`ruby -Ilib test/task_presenter_test.rb` and
`ruby -Ilib test/overlay_loader_test.rb` for the presenters and the loader, and the
throwaway runtime check, which renders every page over HTTP, and
`test/browser/navigation_check.cjs`, which checks the script in a browser.

## Intended OpenProject wiring

OpenProject plugins are Ruby gems. A later deployment task should add the
plugin to OpenProject `Gemfile.plugins` similarly to:

```ruby
group :opf_plugins do
  gem "openproject-replan_overlay",
      path: "../plugins/openproject-replan_overlay",
      require: "open_project/replan_overlay"
end
```

Then the OpenProject runtime needs the normal plugin install/restart flow for
its deployment shape.

## Configuration

The plugin loader reads the overlay from:

```text
REPLAN_OPENPROJECT_OVERLAY_PATH
```

If the variable is unset, the development fallback is:

```text
public/replan/openproject_overlay.json
```

An overlay is shown only to the OpenProject project it names in
`openproject_project_id`; any other project with the module enabled is told
it has no overlay yet. To serve several projects, keep one overlay per
project in a directory and name it in:

```text
REPLAN_OPENPROJECT_OVERLAY_DIR
```

with each project's file at `<project identifier>/openproject_overlay.json`
or `<project identifier>/raw/openproject_overlay.json`. A project without a
directory of its own falls back to the single file above, under the same
rule.

The file should be generated by:

```sh
replan report dashboard --project <project> --week <week> --output reports/latest --format html
```

## Safety

Do not put private RePlan API tokens, OpenProject API tokens or SSH tunnel
details into this plugin. The first version reads a local or internally served
static artifact server-side and renders HTML through OpenProject session
access.
